Get started

Quick start #

evrd keeps your IRC connection alive while you're away, buffers what you miss, and lets clients (native or web) attach and detach whenever you like. The quickest way to run it is with the published container images: ghcr.io/4evrd/evrd (the daemon and evrctl) and ghcr.io/4evrd/evrd-web (the web app on nginx).

  1. Make a secret key

    It encrypts the network passwords evrd saves (NickServ, SASL). Keep a copy somewhere safe; without it they can't be read back.

    shell
    echo "EVRD_SECRET_KEY=$(docker run --rm --entrypoint evrctl ghcr.io/4evrd/evrd genkey)" > .env
  2. Write a config file

    A single node needs no external database: SQLite holds accounts and an embedded Pebble store holds history.

    evrd.conf
    listen     ircs://:6697
api        :8098
db         sqlite:/var/lib/evrd/evrd.db
history    pebble:/var/lib/evrd/history
public_url https://bnc.example.org
irc_host   bnc.example.org
  3. Start evrd and the web app

    The web image proxies /api and /auth to a host named evrd-api on port 8098, so name the daemon's service that.

    docker-compose.yml
    services:
  evrd-api:
    image: ghcr.io/4evrd/evrd:latest
    command: ["-config", "/etc/evrd/evrd.conf"]
    environment:
      EVRD_SECRET_KEY: ${EVRD_SECRET_KEY}   # from .env
    volumes:
      - ./evrd.conf:/etc/evrd/evrd.conf:ro
      - evrd-data:/var/lib/evrd
    ports:
      - "6697:6697"   # IRC — clients attach here
    restart: unless-stopped
  evrd-web:
    image: ghcr.io/4evrd/evrd-web:latest
    ports:
      - "8080:80"     # web app; put TLS in front of it
    restart: unless-stopped
volumes:
  evrd-data:
  4. Create the first admin
    shell
    docker compose exec evrd-api evrctl -config /etc/evrd/evrd.conf \
  user add -admin james 'a-long-password'
  5. Sign in and add a network

    Open the web app (port 8080, or your public_url once a TLS proxy is in front), sign in, and add a network such as irc.libera.chat on +6697. evrd dials it, registers, autojoins your channels and starts buffering. Then attach a native client.

Passwords need at least 10 characters. A password an admin sets is temporary: the user picks their own at next sign-in. Testing over plain http first? Add cookie_secure no to evrd.conf until TLS is in front, or the browser won't keep you signed in. For Postgres and metrics, the repository's deploy/docker setup has them ready.

Get started

Build from source #

evrd is pure Go (no cgo), so it cross-compiles anywhere Go 1.26 runs. The web client is a Svelte 5 + Vite app built with pnpm.

shell
git clone https://github.com/4evrd/evrd.git && cd evrd
make build       # bin/evrd and bin/evrctl
make web         # web/build
./bin/evrd -version
./bin/evrd -config evrd.conf

Development stack

make up runs the whole stack with hot reload: an upstream ergo IRC server, two evrd nodes behind nginx, Postgres, ScyllaDB, VictoriaMetrics and the web client on http://localhost:5173. make e2e runs the Playwright suite against it.

Use evrd

Web client #

The web app shows your networks, channels and private messages with unread counts, mentions, members and topics, and stays in sync with every attached IRC client. Anything you send there shows up in your other clients too, because all sessions share one upstream connection.

The chat input understands /join, /part, /msg, /query, /me, /notice, /nick, /topic, /mode, /kick, /close, /quote and /help, and runs *status commands with /status help.

Use evrd

Native IRC clients #

Point HexChat, irssi, WeeChat or any other IRC client at the bouncer and authenticate with a server password:

Server passwordAttaches to
user:passwordyour default network
user/network:passworda specific network

The password is either your account password or an IRC client password made on the web app's IRC clients page. Client passwords are the only option for accounts that sign in with SSO, and you can revoke them one client at a time.

irssi
/connect -tls bnc.example.org 6697 james/libera:a-long-password

What you get on connect

  • The welcome burst, your channels with names and topic, backlog replay, then live traffic.
  • /join and /part update the network's saved channel list, and /nick changes your nick upstream.
  • Your own notices and /me actions are saved and shown on your other clients.
  • Capabilities echo-message and server-time.

Channel events in backlog

Joins, parts, quits, kicks, nick changes, topics and modes are saved alongside messages. On replay they come from *buffextras as plain text, for example bob is now known as robert, the same way ZNC's buffextras module does it, so they never confuse a client's nick list.

Port 6667 is plaintext. Use 6697 with TLS anywhere outside a private network, and set tls_cert / tls_key for a real certificate.

Network settings #

Each network has its own page in the web app (/networks/<id>) with everything ZNC offers without modules.

  • Servers: several, each with host, port, TLS and an optional server password. evrd connects to the first and moves to the next each time the link drops.
  • Identity: nick, alternate nick, ident, real name, quit message and bind host. Empty fields use the account defaults.
  • Authentication: SASL PLAIN account and password, sent as PASS if the network has no SASL.
  • Certificates: verify with system CAs (TrustPKI), trust everything (TrustAllCerts), or trusted SHA-256 fingerprints. When a certificate is refused, its fingerprint is shown with a button to trust it.
  • Channels: key, detached (joined and logged but hidden from IRC clients until they /join), join-on-connect.
  • Advanced: encoding for non-UTF-8 networks, flood protection (lines per second and burst), join delay.

Per-user settings

Under Account → Bouncer: default ident, quit message and bind host; how many lines to play back, and whether channels and private messages only replay what arrived since you were last attached; timestamps for clients without server-time; fixed CTCP replies; and the addresses allowed to sign in.

Configuration #

evrd reads one plain-text file of directive value lines; pass it with evrd -config evrd.conf. These are the directives you'll set first:

DirectiveExamplePurpose
listenircs://:6697IRC listener; repeat for irc+insecure://:6667

historyscylla://h1,h2:9042/evrdChat history; pebble:/path for one node
tls_cert / tls_key/etc/evrd/*.pemReal certificate for the IRC listener
public_urlhttps://bnc.example.orgWeb app address (and SSO callback)
irc_hostbnc.example.orgHostname shown to users for attaching
max_networks0Per-user default, 0 = unlimited

backlog_lines2000Kept per channel, pruned every 10 minutes

History backends

Chat history never goes in Postgres. ScyllaDB is shared by every node, with one partition per buffer per month and queued writes so a slow database never stalls IRC. Pebble is an embedded store on local disk for single-node installs. evrctl history copy <from> <to> moves history between them.

Accounts and sign-in #

Every user has a role (user or admin), per-user limits and optional suspension. Web sessions are stored in the database behind an HttpOnly cookie, so they survive restarts, and users can see and revoke them on their Account page.

SSO with OpenID Connect

Use Logto or any OIDC provider; SAML and social logins are connectors in the provider. Accounts are created on first sign-in and linked by the token's subject.

evrd.conf
public_url         https://bnc.example.org   # callback: <public_url>/auth/callback
oidc_issuer        https://id.example.org/oidc
oidc_client_id     <app id>
# secret: oidc_client_secret, or EVRD_OIDC_CLIENT_SECRET
oidc_label         IRCforever account
oidc_auto_create   yes
oidc_link_existing no
oidc_admin_role    evrd-admin

Suspending a user signs them out everywhere, drops their IRC clients and disconnects their networks; lifting the suspension reconnects them. The last active admin can't be demoted, suspended or deleted.

Server settings #

Admins can change most of evrd.conf from Admin → Settings. Each value comes from, in order (later wins):

  1. built-in defaults
  2. evrd.conf
  3. the database: values set on the Settings page, shared by every node
  4. the environment (EVRD_…) on that node

Most settings apply live on every node within a few seconds. public_url, the SSO provider and metrics export are marked Restart needed. Startup settings (listen, api, db, history, TLS files, cluster identity, secret keys) stay in the file or environment.

settings_write_conf yes writes values set in the UI back into each node's own config file. Use it on a single node; in cluster mode, leave it off and let the database be the one place these settings live.

Saved passwords #

Network passwords (SASL, NickServ and server passwords) are encrypted in the database with AES-256-GCM under a key that lives outside it. Account and client passwords are bcrypt hashes either way.

evrd.conf
# make one with: evrctl genkey
secret_key      <32 bytes, base64>   # or EVRD_SECRET_KEY, or secret_key_file /path
secret_key_old  <previous key>       # optional: still decrypts while rotating

Rotating the key

Set the new secret_key, move the old one to secret_key_old, restart, then remove the old key. At startup evrd encrypts anything saved before a key was set and re-encrypts anything under an old key. Every node needs the same key; keep it out of database backups.

Running several nodes #

Run any number of nodes against the same Postgres and ScyllaDB, behind a plain round-robin load balancer for IRC (TCP passthrough) and the API (HTTP + WebSocket). Each user is owned by one node, which runs their network connections and serves their clients; any other node forwards that user's traffic to it.

If a node dies, its users move to the others in about 20 seconds (cluster_lease); on shutdown a node hands them over at once.

every node
internal_listen      :8099   # internal HTTP — between nodes only
internal_irc_listen  :6699   # internal IRC — between nodes only
history              scylla://db1,db2/evrd

# per node, in the environment:
EVRD_NODE_ID=node-a
EVRD_INTERNAL_URL=http://evrd-a.internal:8099
EVRD_INTERNAL_IRC_ADDR=evrd-a.internal:6699
EVRD_CLUSTER_SECRET=<the same long random secret on every node>

See the architecture page for diagrams of each deployment shape, request routing and failover.

The repository ships a tested nginx config (deploy/lb.conf) and a Traefik equivalent (deploy/traefik/, Traefik ≥ 3.7 for TCP health checks). A lone node without internal_listen still works and owns every user.

Connections to networks #

Large networks throttle and cap connections per source address, and every user on a node would otherwise share the node's address.

evrd.conf
connect_rate     5                       # most connects/second to one server, per node
upstream_bind    192.0.2.10 192.0.2.11   # spread users over these (stable per user)
upstream_prefix6 2001:db8:42::/64        # or: an IPv6 address of their own per user
bindhost         192.0.2.20 vhost.example.org

A prefix needs Linux and a local route: ip -6 route add local 2001:db8:42::/64 dev lo. bindhost lists addresses users may pick to connect from, like ZNC's BindHost. Admins can use any address and can lock a user's choice.

Metrics #

evrd exports OpenTelemetry metrics over OTLP/HTTP and reads them back from VictoriaMetrics for the dashboard's traffic chart and health numbers.

evrd.conf
otel_endpoint http://victoriametrics:8428/opentelemetry/v1/metrics
otel_interval 15s
metrics_url   http://victoriametrics:8428

Run VictoriaMetrics with -opentelemetry.usePrometheusNaming to get evrd_irc_lines_total, evrd_upstream_up, evrd_upstream_lag_seconds, evrd_irc_clients, evrd_cluster_users, evrd_history_queue and friends. Without metrics_url the dashboard still works, and the chart says metrics are off.

Releases and versions #

Releases are cut automatically by semantic-release from Conventional Commits on main. Each release is tagged vX.Y.Z, gets GitHub release notes grouped by type, and publishes images as :X.Y.Z, :X.Y, :latest and the commit sha. evrd -version reports the version.

CommitRelease
fix: …, perf: …patch
feat: …minor
feat!: … or BREAKING CHANGE:major

evrd stays at 0.x until a breaking change says otherwise. Get the latest release →
